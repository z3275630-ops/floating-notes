# 浮记 v3.1 演进评审提案

日期：2026-11-08。状态：**proposed**。对照现有 v3.0 文档、34 项任务、24 个页面、JSON 契约，以及外部 Gemini「Floating Notes V4 Evolution Proposal」。

> 本文提出产品与开发顺序的变更建议。合并此 PR 不表示 v3.1 已成为现行规格，更不表示功能已实现。F01–F20、T01–T34、现有用例、schema 与已接纳 ADR 继续有效。

## 结论与原则

产品核心闭环为：无负担记录 → 本地可靠保存 → 再次遇到旧记录 → 沿真实证据继续思考。液态玻璃、柔和渐变、动画跟手感是重要体验要求；中文输入、数据可恢复和文字清晰拥有更高运行时优先级。

| Gemini 的建议 | 评审决定 | 涉及现有功能/任务 |
| --- | --- | --- |
| 跨应用系统分享、选中文字捕获 | **优先吸纳**：先 Share Sheet / ACTION_PROCESS_TEXT，再评估可选侧边悬浮球 | F01/F18，T29 |
| 编辑边缘的历史回响、冲突提示气泡 | **优先吸纳**：本地召回优先；证据可追溯、用户可静默/关闭 | F06/F07/F08/F09，T16/T17/T20 |

## 交互验收与安全边界

**跨应用捕获**：先复用系统 Intent 接入同一个草稿/保存服务，预览来源、内容、取消、保存状态；来源缺失时如实显示。第三方应用不一定提供所需选中文本接口。覆盖层需用户主动授权，权限被拒绝仍要允许普通分享。不把常驻悬浮录音当首版必需。

**边缘气泡**：仅在用户停顿后异步检索，输入法 composing 期间不得抢焦点、改变选区或阻塞保存。“历史回响”展示真实片段；“可能矛盾”需要核对双方原文、时间和上下文，不能凭向量相似度认定打脸；“提出一个问题”是可忽略的建议。证据须保留 note_id、revision、block_ids，并遵循 scope、删除/过期/撤销过滤。气泡设节流和关闭开关；没有模型时退化为相关笔记。

**概念对撞**：两张卡都来自实际存在且已授权的笔记；解释为可能关联，点击可追溯全文。用户可重抽、判定牵强、保存为**新**笔记。禁止默认修改、合并或删除原记录。

**视觉与导航**：保留记录/探索/Agent/笔记库四个可发现的入口，空间缩放只在适用局部试验。GlassSurface 保留实色/标准/增强档，AGSL RuntimeShader 的高版本平台要求不能变成所有设备的硬门槛。文字与光标不参与折射，背景不持续耗电动画；TalkBack、200% 字体、减少动画、屏幕返回都有可用替代。

## 与现有契约的冲突点

1. `note-document.schema.json` 对根和块采用 `additionalProperties: false`。新增 physics_meta/vitality_state 前必须设计版本化迁移、更新正确的 schema 分支与 fixtures；**本 PR 不修改现行 NoteDocument v1**。
2. 浮力及回响时间作为可重建派生数据，不因浏览、召回或模型排序改写权威 Note revision。checkbox 的完成状态仍以正文块为准。
3. `scripts/check_docs.py` 的自制 JSON Schema 验证器尚不支持 `number` 类型；不能直接新增浮点浮力字段后声称验证通过。
4. `evidence.schema.json` 当前是来源与覆盖率契约，没有 relation_type。supports/contradicts/bridges/evolves_from 宜作为独立的关系/推理对象引用 EvidenceBundle，避免将模型假说包装为来源事实。
5. UI 气泡、概念碰撞检索、夜间调度三者职责不同；不宜全部无条件加入可写的 `tool-registry.json`。延续 ADR 0004 的 scope、审计、写入幂等和授权要求。
6. 原 ADR 0001 已承诺 Kotlin/Room 本地优先，ADR 0005 是后期服务端方案。重点调整首版顺序，无需废弃全部云端规划。新 [ADR 0008](../decisions/0008-progressive-local-ai.md) 专门评估渐进端侧 AI。

## 开发次序和验收

第一阶段按 [首个 APK 垂直切片](../delivery/first-apk-vertical-slice.md) 跑通 T01/T02/T03/T04/T07/T08，本地文本+checkbox、可靠保存、键盘、玻璃转场与真机采样。七天只能当冲刺愿望，不能当正式交期。

后续在依赖满足时引入系统分享、检索、关联气泡、双卡漫步，最终继续 T19+ 的 Agent、服务端、地图、同步、MCP 与完整 F01–F20 验收。每次正式变更时再同步 feature-contracts、screens、motion、acceptance、task-catalog、schemas、fixtures，不能仅凭本提案就修改既有任务状态。

**关键用例**：离线写入/强杀恢复；分享取消不重复保存；中文候选不被气泡抢焦点；虚假冲突不出现；双卡保存不覆写来源；减少动画可用；无真机或构建时标注 blocked。
