# 给产品所有者的项目说明

这个项目最终要做到：打开就能顺手记录，过去写过的内容能再次被发现，AI 的回答能回到原文；整个过程有清晰、轻盈的玻璃质感和跟手动画。

## 你已经决定的事

Android 是首发平台。你看重完整的 flomo 式体验，也需要备忘录式编辑和待办。液态玻璃、渐变、流畅度是核心要求。开发者无权为了省事把 Agent、漫步、洞察删掉，或把主要页面做成普通白底列表就交差。

## 技术选择交给开发者负责

原生 Android 负责输入、动画和本地保存。数据库相当于手机里的资料柜；同步负责让不同设备的资料一致；备份相当于可以找回的历史副本。AI 会通过受控制的工具读取被允许的笔记、引用原文、保存用户明确要求保存的结果。

这些能力会逐步实现。每一阶段都应给你可操作的版本、短视频和清楚的完成说明。计划文件里的“设计完成”不等于应用已经做好。

## 你每次只需要关注这些验收问题

| 看到什么 | 怎样判断 |
| --- | --- |
| 记录页面 | 能否立即写，键盘弹出是否顺畅，文字会不会乱跳 |
| 玻璃导航和输入面板 | 能看见柔和背景层次、细边高光和轻微厚度；文字清楚，颜色不脏 |
| 动画录屏与真机 | 连续点、快速滑动、中途返回都跟手，不能等动画播完才能继续 |
| 随机漫步 | 能随意走、返回、换方向；不逼你总结或打卡 |
| AI 回答 | 点来源能找到对应笔记；没依据时明确说明 |
| 数据恢复演示 | 删除能撤销，备份恢复不会把现有内容清空 |

用户审美验收与性能测量各有作用。录屏好看不能证明低端机不卡；帧率合格也不能证明界面好看。两个结果都要提交。

## 什么时候才需要你拍板

需要付费服务、公开发布、改变核心功能范围、替换已发布应用身份、上传此前未授权的个人资料时，开发者必须说明具体后果，再请你决定。组件选型、文件拆分、常规修复和测试应由开发者自行完成。

当前不需要购买服务器或模型套餐。M0 先验证最难的视觉、输入和 AI 证据链，用实测估算后续成本。预算批准前只能使用本地模拟或已授权的开发额度，不能自动开通收费服务。

## 完整版本的含义

完整版本覆盖 F01–F20，含 2D 认知地图、MCP/API、增量同步和可靠备份。3D 地图、多用户团队协作、无限嵌套块编辑器不在首个完整版本要求内。所有延期必须明确记录，不能把未完成项改名成“高级功能”后宣称全部交付。
