# ADR 0008：渐进式本地检索与可选 AI 推理

日期：2026-11-08。状态：**proposed**。

## 背景

ADR 0001 已确定 Kotlin/Compose/Room 本地记录，ADR 0004 定义证据与受控工具，ADR 0005 保留 FastAPI/PostgreSQL/pgvector/S3 服务端。v3.1 拟增加边缘关联气泡和概念对撞，需要在无服务器时也能验证部分价值。

## 建议决策

1. Note、Draft、block_id、revision、checkbox 以 Room 为权威；索引/模型/同步失败不得阻止本地记录和恢复。
2. 先实现本地关键词检索。端侧 Embedding、SQLite 向量扩展、模型大小和运行时必须经过真实中文及中英混合样本、低内存设备和许可证验证，不预先承诺所有设备可运行本地 LLM。
3. 关联气泡先本地召回；若需要推断观点冲突或桥接假说，采用统一推理接口，使用已配置的端侧引擎或经用户授权的远程模型。缺失模型则仅展示可核验的相关笔记。
4. 强制 scope 过滤、版本化 EvidenceBundle、用户授权、费用预算、撤销、写入幂等及审计。没有授权不得外发私人笔记；模型输出不作为原文事实。
5. 向量索引可重建，并记录 embedding 模型 ID、版本、维度、水位和删除失效；更换模型时重建隔离索引。服务端 T19+ 仍保留。

## 代价与验证

纯云端前置成本更高，纯端侧强制推理在设备兼容和质量上风险高。渐进方案需要适配层及测试矩阵。T05/T16/T17 验证中文召回、权限和索引重建；T02/T03 验证输入延迟、温升、内存；T20/T21 用带引用的真实标注样本验证反调观点、越权与取消。证据未达标前维持 proposed。
