# 开发、审阅与发布流程

## 1. 从任务到 PR

路线图任务有 ID、依赖、输出、验收。开始前核对当前代码、最新主分支和别人认领的任务；在 Issue/STATUS 中记录分支与范围。实现前确认功能编号和状态合同。新技术决策写 ADR；小型局部实现无需创建冗长会议记录。

分支从 main 创建，命名 `feat/Txx-topic` / `fix/Txx-topic` / `docs/Txx-topic`。保持一个任务一个可审阅闭环。先完成本地检查，再创建 draft PR；具备全部证据后转为 ready。不要把半实现按钮接入正式导航制造“已支持”的错觉。

## 2. 完成定义

实现完成需要正常和错误路径、数据迁移、离线与恢复、必要无障碍和测试。功能 verified 需要对应质量门槛证据。文档写完、截图好看、模拟返回有内容都只能说明各自范围，不能推导完整功能完成。

每个 PR 写明：用户触发情境、最终行为、关联 F/T/Q、改动范围、验证命令与结果、风险和退回办法。视觉 PR 附浅深色截图、完整操作录像、设备/刷新率/build SHA。数据 PR 附迁移和恢复计数；AI PR 附固定评测集差异。

## 3. 检查矩阵

| 变更 | 本地必须 | CI / 发布必须 |
| --- | --- | --- |
| 仅文档/契约 | check_docs；链接/JSON/映射检查 | 同一 docs-contracts 检查 |
| Android 业务 | 编译、lint、相关 JVM 测试 | assembly、lint、单元与关键集成 |
| 数据库 | 每个正式 schema 到新版本迁移、故障恢复 | schema 导出与迁移矩阵 |
| UI/动效 | Compose UI 状态、录屏、交互检查 | 截图回归；关键路径真机帧时间 |
| 服务 API | 类型/静态检查、单元、数据库集成 | auth/scope/幂等/契约 fixture |
| AI | 引用、范围、预算、取消和幂等评测 | 固定语料评估，实模型消耗须授权 |
| 同步/备份 | 双设备冲突/坏包/中断 | 恢复演练与 hash 校验 |

Android Gradle 工程与 CI 已由 T01 建立，真实命令见 [构建说明](../engineering/android-build.md)。服务端尚无工程；不得预先编造测试通过记录。测试不能只重复实现逻辑，必须验证用户可见结果或重要不变量。

## 4. 审阅与合并

主分支只合并检查通过的变更；有独立审阅者时至少一人，单人时记录自审清单和局限。产品所有者主要验收功能体验与视觉，不承担代码审阅。语义/数据/安全争议由工程负责人给明确方案，涉及范围/费用/隐私的决定让所有者拍板。

仓库权限支持时设置 ruleset：PR 合并、required docs-contracts、禁止 force push、禁止删除 main；应用工程建立后追加真正存在的检查。不能勾选不存在的检查把项目锁死。若私人仓库套餐不支持强制保护，记录为流程约束，不能声称已技术强制。

建议 squash merge，合并前确认没有敏感数据和未解决阻断。删除任务分支属于可恢复仓库操作，但不得删除他人仍使用的分支。不要顺手改无关仓库设置。

## 5. 版本与发布

文档版本独立：v3.0 代表当前规格。应用早期版本 `0.x`；F01–F20 和所有发布门槛通过后才能讨论 `1.0.0`。versionCode 单调递增；发布 tag 绑定不可变 commit、签名构建与 changelog。

内测包说明已实现范围、已知问题、数据格式兼容、是否需重新安装。正式升级不可要求卸载清库作为常规方法。发布前构建归档 APK/AAB、映射文件、依赖/SBOM、schema、版本说明和恢复路径；签名密钥不入仓库。

先内部合成数据测试，再所有者内测，再小规模真实数据验证，最后公开分发。公开发布与付费服务开通需要对应授权。出现数据丢失/越权/严重输入卡顿时停止扩大分发，保留版本和诊断信息。

## 6. 回滚

UI/业务回退优先修复版本与开关；数据库不能假设降级 APK 可打开新 schema。所有迁移设计兼容窗口，必要时导出恢复而非直接降数据库。服务端 schema 采用 expand/contract；生产迁移前备份并验证恢复。灰度开关不能让用户记录消失。

## 7. 文档维护规则

产品 feature-contracts 定义“必须有什么”；screens/motion 定义“怎样表现”；数据/API/AI 定义“怎样一致执行”；acceptance 定义“怎样证明”。contracts 内的 token 数值与状态表为机器可读镜像。变更同时更新涉及文件；档案 archive 只用于追溯，不优先于当前规格。

规格相互矛盾时先暂停相关实现并写出冲突与推荐解法，修订后继续。无需暂停无关工作。性能目标不能通过把门槛悄悄调低来变绿；必须附设备和用户体验影响，取得产品范围相关决定。
