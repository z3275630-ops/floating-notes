# 浮记：Android 笔记 App 完整设计与实施方案

版本：设计提案 v2.0 · flomo 功能研究修订版 ｜ 日期：2026-11-08

定位：以 Flomo 的快速记录、主动回顾和基于个人笔记的思考体验为重要参考，融合备忘录的持续编辑与轻量待办，形成有液态玻璃质感的安卓个人笔记与思考工具。

本版取代 v1 的功能范围、导航和发布清单。每日回顾、随机漫步、相关笔记、自然语言查找、AI 洞察、Agent、记忆档案、认知地图与双向链接均进入正式产品设计。分阶段实施是工程依赖顺序，不表示把这些能力从产品中删掉。

调研方式：阅读 flomo 官方帮助文档、公开产品说明及官网指向的 Android 商店开发者更新记录；没有登录付费账号逐项实测。文中分别标明官方已描述能力、本 App 的设计建议与尚需实机确认的细节。本文未读取当前 IdeaMemo 仓库，不把历史讨论当成现有实现。

“浮记”为工作名。本文中的界面数值、算法参数和性能门槛是待验证的设计起点；未宣称已开发完成或达到性能目标。

## 1. 调研后重新确定的产品目标

上一版过度围绕输入、整理与待办展开，把回顾藏在二级页面，把 AI 和地图排到模糊的未来，遗漏了 flomo 很有价值的一部分体验。本版将“记录以后，还能再次遇见、继续思考”作为主流程。

一个完整使用过程可以是：写下一条真实想法；几天后回顾再次看到它；顺着相关笔记漫步；选中几条进行洞察；带着原文向 Agent 追问；把自己的新理解保存成有来源的新笔记。用户也可以只读一会儿，直接退出，不需要每次产生结论或待办。

技术方向保留 Kotlin + Jetpack Compose、本地优先和统一 Note 数据模型。AI 深度处理允许接入模型服务；全天候定时任务、远程 MCP 和跨设备同步需要另有服务端支撑。完整体验涉及模型与服务端成本，具体按第 12 章的运行模式设计。

### 1.2 调研中的版本差异

- Agent 帮助页仍主要介绍微信入口，并提示以各端实际入口为准；官网指向的小米应用商店更新记录已出现 Agent 对话删除、相关笔记继续探索等内容。可确认安卓产品已有相关能力，不能把它描述成只存在于微信。[F-I][F-Q]
- 随机漫步帮助页仍写着不能从指定笔记开始、不能保存小径历史；安卓更新已列出相关笔记“继续探索”。后者支持入口正在演进，但尚不足以确认所有平台都有完整路径历史。本 App 会明确设计“从这条开始”和“保留本次路径”，这是我们的目标能力。[F-E][F-Q]
- 帮助页的 MCP 会员说明与安卓商店“Pro 可使用 MCP”的更新出现差异。本文不锁死 flomo 的套餐权益，功能研究也不以付费档位决定是否设计。[F-P][F-Q]
- 地图公开说明有更新周期和样本规模限制；其可视化呈现不能当作无遗漏的全库统计。本 App 需直接显示覆盖范围与更新时间。[F-K]

### 1.3 应保留的产品气质

快速入口保持轻，不要求先分类。回顾允许闲逛，洞察允许提出问题，Agent 允许说“没有找到足够依据”。AI 提供的新内容与用户真实记录保持来源区分。视觉精致，但不让用户每天面对一个复杂控制台。

## 2. 功能如何真正连起来

### 2.1 六条主流程

| 用户意图 | 具体流程 | 结果 |
| --- | --- | --- |
| 留住想法 | 文字/语音/分享 → 草稿 → 笔记 | 内容及时保存，稍后可整理 |
| 再看看自己 | 每日回顾 → 原文 → 写批注 | 保留当时的自己，也留下今天的理解 |
| 随便走走 | 漫步 → 关联跳转 → 偶尔跨主题 → 结束卡片 | 本次路径可回看，无需强制产出 |
| 想清一个问题 | 找一找 → 选择证据 → 洞察 → Agent 追问 | 结论有依据，可保存为新记录 |
| 了解长期变化 | 地图/统计 → 时间筛选 → 主题 → 原文 | 看见记录中的变化，避免把笔记量当能力评分 |
| 推进事情 | 笔记清单 → 待办/提醒 → 回顾结果 → 更新笔记 | 行动与当初的想法仍能相互定位 |

### 2.2 一条完整的示例旅程

你写下：“今天小组讨论接不上话，当时想补充，又怕说得不合适。”

保存后出现一个不打断输入的“看看相关记录”。你打开后看到以前的练习总结与读书摘录，选择继续漫步。在第三条停下来，追加一句新理解。

你把本次选中的四条记录交给“寻找例外”的洞察视角。系统如果发现你在某次熟悉的小组里表达更顺畅，必须引用那条记录；如果没找到，就直接说明材料不足。

然后点“继续聊”，问 Agent：“这几次顺畅的时候，有哪些共同条件？”Agent 沿用同一组来源，也可以在你允许的范围内扩大检索。最后你说“把刚才那条练习记下来”，应用创建有来源的新笔记，提供撤销。

这个例子描述期望流程，不预设 AI 会对你作出什么心理判断，也不要求每场漫步都走到最后一步。

### 2.3 所有功能共用的范围选择器

时间、包含标签、排除标签、笔记本、来源类型、媒体类型、归档状态，使用同一套 NoteScope 定义。它在搜索、回顾、洞察、地图和 Agent 中共享语义。

用户在“沟通”标签里启动洞察后，界面要明确保留这个范围。Agent 如果扩大到全库，要显示范围变化；工具层不能偷偷突破排除项。

## 3. 页面架构重排

底部默认改为 **记录｜探索｜Agent｜笔记库**，新建按钮置于拇指易触达的位置。四个入口先作为正式原型的测试方案，经过小屏可达性测试再调整具体样式。

| 页面 | 一级内容 | 深入入口 |
| --- | --- | --- |
| 记录 | 时间流、快速输入、置顶与待办筛选 | 详情、编辑、语音、相关笔记 |
| 探索 | 今日回顾与继续上次漫步 | 随机漫步、洞察、认知地图、记录统计 |
| Agent | 对话和最近任务结果 | 技能、定时任务、记忆中心、资料范围 |
| 笔记库 | 多级标签、笔记本、收藏和保存的搜索 | 历史、回收站、导入导出、设置 |

待办通过记录页的固定筛选与笔记库入口访问，可设为默认启动视图。它不占据 Agent 或探索的唯一入口。启动页允许选择记录、待办、上次页面或指定标签。

探索页不堆满九宫格功能卡：上半部只突出“今日回顾”，保留一个清晰的“开始漫步”按钮，下方展示最近一次洞察与地图入口。没有历史时给出可执行的空状态。

短记、长文和清单继续共用 Note。引用关系、语义相似关系、Agent 对话记忆是不同对象，不能写成同一种连线或统一当作用户事实。

## 4. 页面与功能详细规格

### 4.1 记录与编辑

- 默认无标题、无需先分类；支持段落、标题、加粗、高亮、列表、勾选项、引用、图片、音频和视频附件。
- 首页单列，长文显示摘要；进入详情后连续阅读，超长文本不强行缩小字号。
- 从笔记流、搜索、回顾进入同一条内容，始终保留相同 ID。
- 快速输入保存草稿；已有笔记自动保存。关闭输入面板保留非空草稿，提供明确丢弃入口。
- 本地提交完成后再显示保存成功。新笔记保存后可出现“相关笔记”轻入口，不能自动弹 AI 对话。
- 短距离侧滑显示“相关、洞察”等动作，长按菜单提供同等入口；手势与安卓系统返回区域分别测试。
- 引用使用 @ 检索或“引用这条”，点批注会创建关联的新笔记；反向引用在原文底部显示。
- 选中一段长文也能进入洞察，但必须记录选区和来源版本，避免全文被误当作已选材料。
- 标签、来源、版本和关联信息逐步展开；正文编辑区不长期塞入 AI 按钮阵列。

### 4.2 语音记录

正式提供录音与转写，不再只依赖系统输入法。主按钮的长按是快捷方式，同时提供可见录音按钮，避免功能藏在手势里。

流程：开始录音 → 暂停/继续 → 停止并保存音频 → 转写 → 可选轻整理 → 保存笔记。录音、识别、整理分别显示状态；失败时已经保存的音频仍可播放和导出。

保留三个层次：原始音频、识别文字、整理版。整理默认处理口癖与明显错字，用户可切换原文。人名、金额、时间等不确定片段可标记待核对，不能为了句子顺畅擅自补事实。

断网允许录音后排队转写；重复重试使用同一任务 ID，避免产生重复笔记和重复计费。实际费用只在供应商支持幂等或明确结算能力时才能保证，界面不得笼统承诺重试免费。

录音权限在第一次主动录音时申请。按 Android 版本正确处理 microphone 前台服务、通知和后台启动限制；从桌面入口进入后，先建立合规的用户可见录音状态。[S13]

### 4.3 多级标签、笔记库与待办

多级标签是完整版本的基础功能，支持父子移动、合并、重命名和批量应用。笔记可以挂多个标签；父标签可切换只看本级或包含子级。

底层使用稳定 tag_id 和 parent_id；显示路径变化不改变身份。正文中的标签是带 ID 的引用或可解析标记，不能靠全库字符串替换实现重命名。移动操作要阻止形成循环关系。

笔记本作为可选容器保留，默认不要求每条笔记进入笔记本。标签树和笔记本入口分区呈现，用户可以只使用其中一套。

待办仍来自笔记里的勾选块，拥有稳定 block_id。支持单次日期、延后和基本每日/每周重复；高级重复规则可单独完善。完成待办更新原文，删除或完成后取消对应提醒。归档内容中的未完成待办继续可见并标明来源。

### 4.4 每日回顾

这是规律性重见旧记录的入口。每一天生成一份稳定卡组，刷新页面或换设备不会毫无说明地换一批。

可设置：数量、时间跨度、包含/排除标签、来源、未标注内容、是否包含纯待办、是否包含摘录、提醒时段。提供去年今日等入口，但没有记录时不编造周年内容。

每张卡片可展开原文、写批注、查相关、进入漫步或洞察。反馈包括“稍后再看”“暂时不出现”“排除这类内容”；用户随时能在设置里恢复。

生成策略是本方案的算法建议：结合距上次看到的时间、记录年代分布与主题多样性；保留随机性，减少重复。回顾不默认变成记忆测试；若以后提供背诵模式，单独使用明确的学习调度逻辑。

App 与桌面组件使用同一份 ReviewSession。推送默认隐藏敏感正文，可由用户选择显示。回顾提醒可以在宽松时间窗内送达，不为普通回顾滥用精确闹钟。

### 4.5 相关笔记与“找一找”

相关笔记从当前记录出发；“找一找”从用户自然语言问题出发；精确搜索继续服务明确关键词。这些入口可以共享检索设施，但界面必须说明各自范围。

相关结果同时考虑文字和语义，不强制要求同标签。提供“跨标签看看”选项，并允许用户标记“不相关”。若用 AI 生成关联理由，只能基于双方原文，找不到依据时省略理由。

每条结果可以打开、加入材料篮、继续探索、发起洞察。不要把同一条长文切出的多个片段伪装成多条独立证据。

“找一找”接受“以前有哪些让我更愿意开口的经历”这类问题。先显示找到的原文，再提供“基于这些讨论”的入口。无命中时明确说当前范围没有找到，不能现场生成一段当作旧笔记。

筛选范围必须在关键词候选、向量候选、重排、最终取全文时都生效。用户排除的标签不能从另一路检索偷偷混进来。

### 4.6 随机漫步

这一功能提供连续探索旧记录的体验。本方案借鉴关联游走与结束卡片，增加明确的返回路径与起点选择；具体排序算法属于我们的设计，未声称复现 flomo 内部实现。

入口：随机起点、指定笔记、当前标签、地图上的一个主题。默认随机起点只需一次点击。

漫步页以一张当前笔记为主，显示记录日期和来源；底部是轻量玻璃工具条。主要动作是“继续走”，另有“换个方向”“回到上一条”和“结束”。正文上下滚动，换笔记优先使用按钮，避免长文阅读与横滑误触竞争。

候选池分为相关延伸、跨主题连接和意外遇见。排序先过滤已读、删除、排除和重复记录，再综合相似度、多样性、新鲜度与最近路径。开始可用约 70% 相关延伸、20% 跨主题、10% 意外抽样试验，实际比例依据使用反馈调整，不能作为已验证最佳值。

弱关联跨越需要标明“换条小路”，不捏造因果关系。没有足够笔记时明确提示当前可探索范围，并允许随机换一条。

每次旅程保留 WalkSession 与有序步数，记录起点、候选策略版本、访问笔记 ID/版本、停留和用户选择。默认仅本地保存互动数据，用户可以关闭路径保存。

结束时生成明信片：经过条数、覆盖的记录日期范围、停留片段和新批注。它们由真实路径计算，不用模型猜。分享前可隐藏正文与标签；不自动发到外部。

可选“沿途的几条一起洞察”和“继续聊”。结束本身就是完整体验，不要求保存总结或制定行动。

### 4.7 AI 洞察

洞察作为正式功能，有独立页面与历史记录。输入可以来自单条笔记、长文选区、当前搜索、回顾卡组、漫步中选中的内容、标签或时间范围。

界面先展示“本次材料”：范围、条数、是否抽样、可排除条目。超出预算时说明只选取部分记录，允许收窄或分批处理，不能写“分析了全部”却实际只读前几条。

内置视角建议：主题梳理、寻找例外、观点变化、假设检查、价值澄清、行动尝试、温和鼓励、提出一个好问题。支持保存个人提示词、修改名称、设为常用、调整语气。视角是一组任务规则，不必把每种视角包装成独立 Agent。

洞察输出采用“观察—依据—另一种解释—可继续的问题”的可伸缩结构。材料很少时可以只提出一个问题，避免硬凑长报告。对用户行为的解释标为假设，不用几条情绪笔记下人格或心理诊断。

结果中的事实性回溯使用来源标记；点开显示原文片段、日期、来源类型与版本。生成中可以退出，任务继续与否取决于运行模式；再次进入恢复到真实进度。允许取消、重试、换视角和标记不准确。

结果保持为独立 Insight 对象，用户选择保存时再生成有来源的新 Note。点“继续聊”时携带原问题、视角、证据包和版本，不重新只发送一段没有依据的总结。

### 4.8 Agent 对话与动作

Agent 是一级入口，也能从笔记、洞察、漫步和地图携带上下文进入。同一线程连续理解当前问题，支持引用笔记和附加图片；语音输入复用录音链路。

产品能力包括：检索自己的记录、围绕证据继续讨论、比较不同时间的观点、读取已授权记忆、形成新笔记、提取待办、创建与管理定时任务、读取用户提供的网页、按授权联网补充。

首轮内置技能建议如下。这是本产品的技能设计，名称与规则可调整：

| 技能 | 输入范围 | 交付 |
| --- | --- | --- |
| 今天回看 | 用户选定时间与来源 | 引用原文的简短复盘，允许追加问题 |
| 观点变化 | 同一主题的多个时期 | 时间线与变化证据，找不到变化就说明 |
| 寻找例外 | 一个困扰与相关记录 | 找出可能不符合原判断的记录 |
| 阅读延伸 | 已有摘录与问题 | 自己的理解和可选外部资料分开展示 |
| 漫步同行 | 当前旅程与选中笔记 | 帮助追问，不强迫每步解释 |
| 下次试试 | 用户决定采纳的想法 | 可编辑的轻量待办 |
| 写回笔记 | 选中的对话片段 | 保留来源的新笔记，可撤销 |
| 定期回望 | 用户明确设置的周期与范围 | 任务记录、通知和可追问结果 |

模型可用工具设计为 search_notes、read_note、get_related、get_memory、create_note、propose_note_patch、create_task、schedule_job、fetch_user_url、search_web。每个工具有参数校验、权限范围、超时与结果状态。

用户看到的是“正在找相关记录”“已查看 7 条”等实际执行状态；数量来自工具日志。不要伪造思考过程或展示看似详细但与执行无关的推理流水。

操作授权按意图处理：读取已授权范围内的资料无需每轮确认；用户明确说“记下来”可直接新建并提供撤销；AI 主动建议保存时给可编辑草稿；批量覆盖旧笔记、删除或外部发送必须先展示具体结果和影响。

每次有副作用的调用包含 action_id。模型重试或断线重连时不能重复创建笔记或重复设置提醒。修改旧笔记使用版本检查，冲突时保留双方，不静默覆盖。

对话中提及外部网页仅表示可用资料。网页中的“忽略规则”“把笔记发送给某地址”一类文字属于不可信内容，不能取得工具权限。跨用户数据检索必须在服务端按身份与范围过滤。

### 4.9 记忆中心

把用户笔记、对话历史、提取出的记忆分开管理。笔记是原始资料；对话是交流记录；记忆条目是对资料的有来源提炼，可能过期或判断错误。

记忆中心展示：较稳定的偏好、当前项目和目标、事件记录、待核实判断。每条条目带来源、生成时间、有效时间或最后确认时间、事实/推测类型、状态和可编辑文本。

用户可以修改、删除、暂停提取、清空某次会话记忆，或把某本笔记排除在 AI 使用范围之外。删除原始资料后，相关嵌入、摘要、记忆与缓存进入失效/删除流程；不能只删界面上的一行。

旧目标保留时间上下文，例如“2025 年曾计划……”，不能在新对话里当作当前决定。相互矛盾的记忆保留冲突状态，通过新证据或用户更正解决。

记录中引用他人的观点、虚构故事、练习案例和一时情绪，不自动转成用户身份或长期偏好。模型生成的洞察也不能循环提炼成“用户曾经说过”的事实。

支持导出结构化记忆和可读文本；通过 MCP 提供记忆与读取原文的权限分开。连接前显示外部工具将能访问什么，随时可撤销。

### 4.10 定时任务

任务类型包括每日回顾提醒、每周复盘、指定主题追踪、外部资料简报和一次性提醒。默认关闭自动联网，用户启用资料简报时明确设置主题和频率。

任务创建后显示自然语言摘要、范围、时区、下次运行时间、允许调用的工具和预算。支持编辑、暂停、跳过一次、删除和查看运行历史。

固定时刻提醒与耗时内容生成分开建模。周报可以提前生成，在计划时段发送；生成失败时记录失败并给出重试入口，不能发送一个成功空壳。

手机离线时，本地-only 模式显示待执行；全天候模式由服务端按授权范围执行并投递通知。服务器只能读取已经同步且仍在授权范围内的资料；新写但未同步的笔记不算已分析。

重复任务以用户时区计算，下次运行要处理夏令时、设备调时和重启。任务结果幂等，漏跑可选择跳过或补一次，不能恢复联网后一次推来十份旧报告。

### 4.11 认知地图与关系图

认知地图用内容相似度提供主题全景；关系图呈现明确的引用和批注关系。两者分别提供入口，也可在主题页切换，但不能混淆连线含义。

地图默认 2D：柔和主题区域、可缩放节点、清晰主题名称。选中一个主题，底部弹出原文列表，可继续洞察或从其中一条开始漫步。允许手动重命名主题，但保留机器主题标签与用户命名的关系。

时间轴首先固定当前布局，通过月份筛选高亮笔记，减少切换时间时整个地图重新洗牌。若另外提供“按当时数据重新聚类”，必须明确是另一种观察方式。

图上距离是算法近似，不代表客观知识距离；记录密集也不等于重要程度。标签、聚类主题和人工引用是三种不同依据。稀疏数据仍展示原文入口，不制造虚假的山峰。

大规模数据按主题聚合、按层展开，显示“已覆盖多少/符合范围多少、抽样方式、上次更新”。地图滑动采用空间命中与视口裁剪，不为每个点放一个昂贵的 Compose 组件。

3D 光效和路线动画属于展示增强，基础认知地图与关系探索已纳入完整产品验收，不能用一张静态背景图顶替。

### 4.12 统计、历史与分享

热力图与月年统计反映记录节奏，标签统计和主题变化可打开具体笔记。AI 生成内容、导入内容和自己输入的内容可分开统计，避免自动生成周报把记录量抬高。

历史版本保存文本与附件引用。正文恢复要展示差异；附件是否仍在保留期、能否恢复需明确说明。AI 修改前创建版本，恢复历史后更新检索索引。

分享卡片提供简洁、玻璃渐变、纸感等主题，用户选择导出的条目与可见字段。默认生成本地图片，不创建公开链接，也不自动外发。长内容拆页时保持来源对应。

### 4.13 多媒体、导入导出、同步与外部连接

图片、音频和视频统一为附件对象，列表只读缩略图与元数据。视频默认不自动播放、不做全文视觉分析；这些扩展另设明确开关和费用提示。

优先接收系统分享、常见 Markdown/JSON 和用户合法导出的笔记。flomo 的实际导出格式在拿到样本后再确定解析器；不得杜撰字段、调用其私有接口或假定可以无损还原未导出的关系。

迁移需保留时间、层级标签、附件、来源 URL 和可恢复的引用；有损项列出报告。重复导入先预览重复与冲突数量。

同步采用增量变更、稳定 ID、版本与删除标记；附件按校验值传输，断点续传和重试单独管理。整库 WebDAV 备份继续作为备份使用，不能代替并发同步。

外部 MCP 提供搜索、读取、创建和有限更新，按工具分配只读/可新建/可修改权限，按笔记范围授权。个人 API、快捷方式与 MCP 共用业务服务，不绕过审计和版本检查。

微信等聊天平台入口进入完整蓝图，但实现方式必须基于平台实际支持的官方接入能力、成本和账号条件。Android 原生 Agent 不依赖微信才能使用；不以未经核实的个人号自动化作为唯一入口。

### 4.14 设置与状态

设置包含外观、编辑、回顾、Agent 与模型、记忆与授权、定时任务、数据。提供模型服务连接状态、实际用量、费用预算和权限管理；普通用户无需理解向量维度或图布局算法。

桌面组件包括快速文字、录音入口、每日回顾和 Agent 快捷入口。组件采用平台支持的静态材质，不能承诺把应用内实时液态玻璃原样搬到桌面：Glance 受 AppWidgets/RemoteViews 能力约束。[S12]

所有 AI 任务都有排队、运行、完成、取消、失败和资料过期状态；网络失败不妨碍本地笔记编辑。空笔记库仍能记录和普通对话，但基于个人记录的判断必须说明暂无依据。

## 5. 视觉设计系统

### 5.1 主视觉：雾白、淡紫、冰蓝

浅色底色接近带一点暖意的白，局部光晕由淡紫过渡到冰蓝，再以很浅的薄荷色收尾。渐变主要位于背景顶部与操作区附近，中间阅读区域保持稳定。

| 语义 | 浅色建议 | 深色建议 | 使用方式 |
| --- | --- | --- | --- |
| 页面底色 | #F7F8FC | #11131B | 全页面基底 |
| 正文表面 | #FFFFFF 或高不透明度近白 | #1A1E2A | 笔记与编辑区 |
| 主文字 | #202431 | #EEF1F8 | 长文与标题 |
| 次文字 | #596274 | #AAB4C9 | 时间、辅助说明 |
| 品牌强调 | #6356D9 | #B9AEFF | 少量选中状态与关键操作 |
| 背景光色 | #E4DCFF → #D9ECFF → #DDF4ED | 深色底上降低亮度的对应光晕 | 装饰，不能直接充当小字底色 |
| 错误 | 深红并配文字 | 浅红并配文字 | 保存失败、权限问题 |

颜色是初稿，需在实际透明层合成之后测对比度，不能只核对独立色值。普通文字以至少 4.5:1、较大文字以至少 3:1 作为验收目标。按钮状态也要有形状或文字变化，不能仅靠颜色区分。

### 5.2 玻璃分级

| 等级 | 放置区域 | 效果 |
| --- | --- | --- |
| G0 内容面 | 笔记卡片、正文、长列表 | 稳定实底或很高不透明度，无实时折射 |
| G1 轻玻璃 | 顶部工具条、非高频浮层 | 染色、细边缘高光、柔阴影；可有有限背景模糊 |
| G2 重点玻璃 | 底部导航、快速记录面板外壳 | 背景采样、有限模糊、边缘折射、少量交互形变 |

玻璃需要让人看到厚度和背景层次。仅把卡片透明度调低，往往会让页面显得灰脏。反过来，折射过强又会让文字附近像水波，容易晕。

重点控制以下参数：背景采样区域、染色强度、透明度、边缘高光方向、曲率、阴影和状态切换。正文及按钮标签单独绘制在效果层上方，保持清晰。

初始限制：同一页面常驻高成本玻璃区域控制在 1–2 个；弹出输入面板时隐藏或降级后方导航，避免多层玻璃相互采样。该数量只是调试起点，最终由实际 GPU 成本决定。

### 5.3 间距、圆角、字体

| 项目 | 初始规范 |
| --- | --- |
| 间距刻度 | 4、8、12、16、20、24、32dp |
| 页面水平边距 | 手机默认 20dp，窄屏可降为 16dp |
| 卡片圆角 | 20dp |
| 大面板圆角 | 28dp；与系统窗口形态协调 |
| 胶囊导航 | 按高度形成自然胶囊，不给所有组件套相同圆角 |
| 页面标题 | 28–30sp，中等字重 |
| 正文 | 16sp 起，按系统设置缩放 |
| 辅助信息 | 12–13sp 起，不能承载关键操作说明 |
| 图标 | 统一 22–24dp 线性图标；触摸区至少 48×48dp |

采用系统中文字体与统一图标集。不要为“高级感”大量使用极细字重或加载整套巨大中文字体包。48dp 触摸区域参考 Android 无障碍指导。[S9]

### 5.4 深色与无障碍

深色主题单独设计：降低光晕亮度，提高玻璃染色密度，减少灰白泛光。提供减少透明度后的清晰实底方案。

验证系统大字体、TalkBack、减少动画、色觉差异和深浅色切换。表单与弹层要正确转移焦点，关闭后返回原按钮。选中、待办完成、保存失败都要有可读语义。

### 5.5 需要交付的设计资产

设计资产覆盖记录、快速输入、录音转写、完整编辑、笔记库、待办、精确搜索/找一找、探索首页、每日回顾、随机漫步、洞察报告、Agent、记忆中心、定时任务、认知地图、授权与数据管理。每页覆盖深浅色与必要的空白、加载、失败、资料不足和权限拒绝状态。

组件清单：GlassSurface、玻璃导航、笔记卡片、标签胶囊、输入面板、编辑工具栏、搜索结果、待办行、状态提示、确认弹层、来源引用卡、AI 范围选择器、任务进度、漫步工具条、地图底部面板。组件使用统一 token，不允许每页自己调一套圆角和紫色。

### 5.6 新功能怎样保持同一种美感

- 漫步：当前笔记是清晰内容面，路径与动作落在玻璃工具条；过渡短、可中断，正文不跟着折射。
- 洞察：报告如一张干净纸页，来源标记清楚；“继续聊”和范围面板使用统一材质，避免多彩 AI 卡片抢占正文。
- Agent：输入栏轻玻璃，消息正文稳定；工具过程折叠，只在需要时看来源和操作记录。
- 地图：背景柔和但坐标与轮廓清楚；主题颜色保持稳定，不用渐变颜色表达未经定义的分数。
- 记忆：信息密度适中，事实、待核实、过期状态用文字与标记组合表达，方便纠正。

上一版只有记录/笔记/待办的交互示意不再代表 v2 导航。本轮交付以更新后的规格为准，后续原型应按这些关键页重新制作。

## 6. 动效与跟手体验

| 操作 | 建议表现 | 初始时间范围 |
| --- | --- | --- |
| 按下按钮 | 很轻的压缩与高光变化，释放立即回弹 | 80–140ms |
| 页面切换 | 短距离位移配合透明度，保留空间关系 | 180–260ms |
| 输入面板进入 | 从触发位置附近展开，与系统键盘同步 | 约 220–320ms；以系统动画进度为准 |
| 笔记打开 | 小幅容器扩展或普通转场；测试通过后再引入共享元素 | 200–300ms |
| 完成待办 | 勾选反馈、文字状态变化、位置平滑调整 | 120–200ms |
| 删除/归档 | 行高收拢并提供撤销 | 160–220ms |

这些数值是调参起点。弹簧动画由阻尼和刚度定义，实际时长随距离和初始速度变化，不能机械套用固定毫秒数。

硬性行为：动画可中断；连点不排队播放；手势返回跟随手指；后台和不可见页面停止动画；系统减少动画时移除大幅形变与位移。录入中的文字绝不跟着容器弹跳。

背景默认静止。允许主题切换时短暂过渡，首页进入时很轻的光色变化；不要常驻循环漂浮渐变。

安卓键盘的 WindowInsets 是布局依据。不要自行猜测键盘高度，再给整页叠加一套上下平移动画，这会造成双重位移、底部空洞和光标被遮挡。[S3]

### 6.1 AI 与地图带来的额外负载

模型输出按短时间窗口批量更新界面，避免每个 token 都重组整页。自动滚动只在用户本来位于底部时生效；用户上滑查看来源后，新增回复不得把他强拉回底部。

向量索引、音频处理和地图布局在后台调度；编辑输入和屏幕渲染具有更高优先级。省电模式可暂停非紧急索引，显示覆盖状态，仍允许明确发起的查询。

页面切换保留漫步位置、洞察滚动和 Agent 输入草稿。性能档位只降低视觉成本，不能悄悄取消引用校验或数据保存。

## 7. 技术架构与选型

### 7.1 推荐组合

| 领域 | 选择 | 理由与约束 |
| --- | --- | --- |
| 原生 UI | Kotlin + Jetpack Compose | 沿用你的方向，便于原生输入、手势、状态与生命周期处理 |
| 本地数据库 | Room / SQLite | 离线保存、迁移、事务和查询 |
| 状态 | ViewModel + StateFlow + 单向数据流 | 界面从统一状态渲染，事件可追踪 |
| 设置 | DataStore | 仅存偏好设置，不当笔记数据库 |
| 异步 | Kotlin Coroutines | IO、解析、索引和缩略图处理移出主线程 |
| 图片 | 维护中的原生图片加载库，例如 Coil | 缩略图、缓存、尺寸感知解码；锁定兼容版本 |
| 后台备份 | WorkManager | 适合可延后的可靠工作，不承诺准点提醒 |
| 指定时刻提醒 | AlarmManager + 通知 | 检查权限、系统状态和重新调度 |
| 特效 | 自有 GlassSurface 组件，内部封装 Haze 等候选实现 | 避免业务页面绑定某套实验 API |
| 性能验证 | Macrobenchmark、Baseline Profiles、Perfetto | 使用 release 构建在真机验证 |

新项目可从 minSdk 26 评估起步；已有项目尊重原兼容范围，不为了玻璃效果直接抬高最低版本。targetSdk 和依赖版本在开发时按发布渠道与兼容验证确定，本文不把所有“最新版本”硬塞进项目。

Compose 能实现这一方向，但框架选择本身不能保证流畅。官方也要求通过 release 构建、合理状态处理和性能测量验证。[S2]

### 7.2 模块边界

早期可以放在单个 app 模块，以包隔离职责：ui/designsystem、feature/capture、feature/editor、feature/library、feature/tasks、feature/review、feature/walk、feature/insight、feature/agent、feature/map、data/local、data/backup、core/model。

依赖方向保持简单：界面 → ViewModel → Repository → 数据库/附件仓库。文件导入、备份恢复、提醒调度作为独立服务边界。业务规模确实增长后再拆 Gradle 模块，避免小项目一开始维护大量构建配置。

列表只观察摘要数据；编辑器只观察当前笔记；自动保存一个字不能让整个首页重组。列表使用稳定 ID，图片容器预留尺寸，避免滚动时跳动。

### 7.3 液态玻璃的实现策略

特别注意：Compose 的 Modifier.blur 模糊的是组件自身绘制的内容。直接把它套到带文字的导航上，会把文字也模糊。背景玻璃需要背景采样、效果处理、前景清晰绘制的分层。[S1]

Haze 是可评估的背景模糊和玻璃效果库。作者在 2026-11-02 发布的 2.1 公告中称 Glass API 已稳定，同时仍把原生 Android backdrop 后端和 input sharing 标为实验能力。不能据此承诺所有安卓设备都能承受同等效果，也不要把实验后端作为首版必需项。[S10]

实施顺序：

1. 做一个只含长列表、底部玻璃导航、输入面板的性能样例。
2. 比较纯色基线、背景模糊、加入折射后的帧耗时和内存。
3. 把选定实现封装进 GlassSurface，业务仅传材质等级、形状和状态。
4. 标准档保留模糊、染色和边缘高光；增强档增加轻微折射；简化档用清晰实底、渐变和阴影保持风格。
5. 按 API 能力与实测配置选择默认档。运行中因低电量或持续异常降档要有滞后，避免滚动时画质反复跳变。
6. 完成键盘、弹层、滚动、旋转和截图测试，再将样例组件接入实际页面。

普通 Modifier.blur 的平台支持从 Android 12 起；第三方库能否在更老系统回退，要核对其实际文档与测试结果，不能把一个 API 的限制直接套到所有库。[S1]

### 7.4 编辑器与存储模型

新项目建议采用小型、带版本的文档模型：一个 Note 拥有一份 document_json，里面是平面块列表；每块有稳定 block_id，可表示段落、标题、列表、勾选项和图片引用。首期不要做无限嵌套、拖动块和跨块复杂排版。

文本输入使用原生输入组件。编辑期间保留输入法 composing 区、选区和撤销状态，不要每次输入都序列化再解析回 UI。序列化在合适的后台任务中进行，按 revision 写入。

如果已有项目使用 Markdown 或其他稳定格式，先沿用并增加适配层；迁移格式必须单独立项、可验证恢复。此处的新项目模型不构成重写已有库的理由。

| 数据对象 | 核心字段与规则 |
| --- | --- |
| Note | UUID、author_type、source_type、source_url、ai_scope、可选标题、document_json、document_version、search_text、notebook_id、created_at、updated_at、revision、archived_at、deleted_at |
| Tag / NoteTag | tag_id、parent_id、展示路径与多对多关系；移动防循环 |
| Attachment | UUID、相对路径、媒体类型、大小、校验值、导入状态 |
| Draft | draft_id、目标 note_id 或空、文档、revision、保存时间 |
| TaskIndex | note_id + block_id、展示文字、完成状态、日期；是可重建索引 |
| Reminder | 对应 note_id + block_id、计划时刻、时区、调度状态 |
| NoteLink | source_id、target_id、block_id、关系类型；支撑引用、反链与关系图 |
| BackupManifest | 格式版本、条目数、附件校验值、生成时间 |

文档是待办内容与完成状态的唯一权威来源。TaskIndex 是查询加速层，勾选待办必须在同一事务中修改文档和索引；任务页不能另存一份永远不会同步的文本。

### 7.5 共享检索与推理架构

统一链路：本地提交 → 持久化变更事件 → 规范化/切片 → 更新关键词索引与嵌入 → 查询召回 → 重排与去重 → 权限复核 → 构造证据包 → AI 生成 → 保存结果与来源。

短笔记尽量作为完整语义单位；长文按段落和标题切片，每片保留 note_id、revision、chunk_id 与字符范围。检索后按原文合并相邻片段，不能失去上下文。

关键词与向量检索各有用途，组合使用并单独评估。选定 embedding 模型前用真实中文、口语、短句和中英混合样本验证；模型版本与维度必须写入索引元数据。更换模型时重建隔离索引，完成后再切换，不能混用不同向量空间。

相关笔记、找一找、漫步、地图与 Agent 共享索引设施，各自拥有不同的排序目标。相似度最高不总是最适合漫步；搜索需要精确，漫步需要适度多样，地图需要全局可解释性。

每个 EvidenceBundle 记录实际读取的笔记版本、片段、范围、截断情况与来源类型。生成器只能引用存在于该证据包的 ID。引用存在性可自动校验，语义是否真正支持结论仍需用人工标注样本评估。

新笔记提交后先进入关键词搜索，嵌入可异步补齐。UI 显示语义索引进度，不能让旧索引看起来代表最新全库。更改范围或删除笔记后优先执行失效与权限过滤。

### 7.6 Agent 与任务服务

模型适配器负责服务接口，业务工具负责实际动作，调度器负责长任务。模型不能直接拿数据库凭据或绕过业务层执行任意 SQL。

AgentRun 保存状态、范围、工具预算、实际用量、产生的结果与引用。流式断线支持按 run_id 继续读取；恢复时不会重新执行已提交的写入动作。

任务队列使用可重试但幂等的处理方式。每个步骤有超时、取消标记与结果检查；外部模型调用在返回前后检查任务是否仍有效。用户撤回授权后停止后续读取，正在执行的外部请求能否中止以供应商能力为准，并如实记录。

整库总结采用明确范围下的分组摘要与原文回查，报告实际覆盖笔记数。只取几个相似片段无法回答“我这一年所有变化”，这种问题要走聚合任务。

### 7.7 新增数据对象

| 对象 | 必要字段与规则 |
| --- | --- |
| NoteVersion | note_id、revision、文档快照、附件引用、编辑来源、时间 |
| NoteChunk / Embedding | 版本、切片范围、模型 ID/版本、维度、索引状态 |
| ReviewSession / ReviewEvent | 日期、范围快照、固定卡组、已看和排除反馈 |
| WalkSession / WalkStep | 起点、访问顺序、策略版本、分支、笔记版本 |
| EvidenceBundle | 范围、实际引用版本、抽样/截断说明、内容校验值 |
| Insight | 原问题、视角版本、证据包、生成状态、结果、用户反馈 |
| Conversation / Message | 会话范围、角色、内容、引用、来源入口 |
| AgentRun / ToolAction | run_id、action_id、授权快照、执行状态、幂等结果 |

## 8. 保存、备份和迁移：发布前就要可靠

### 8.1 自动保存协议

快速输入保存为草稿，点击保存后正式提交；编辑已有笔记自动更新本地版本。

- 输入先进入内存编辑状态，短暂停顿约 300ms 后落盘。
- 持续输入也设置约 1 秒的最大合并窗口，避免仅 debounce 导致一直不写盘。
- 写入按笔记串行化或做 revision 校验，旧异步任务不能覆盖新输入。
- 每次保存提交文档及相关索引，附件使用可恢复的导入状态。
- 状态必须区分“正在保存”“已保存到此设备”“保存失败”。
- 用户明确退出编辑时尽量完成最新提交；正常生命周期回调也补做保存，但不能只依靠退出回调。
- 突然断电或进程被强杀时，尚未落盘的极短输入窗口仍可能丢失；开发时通过草稿恢复和故障测试尽量缩小，不能写“永不丢失”。
- 不把“已在本地保存”写成“已备份”，网络备份有独立状态。

### 8.2 附件

通过系统文件或图片选择器导入，及时复制到应用管理目录或正确保留持久授权。仅保存临时 content URI，过一段时间可能打不开。

采用临时文件 → 完整写入 → 校验 → 原子改名 → 数据库登记的可恢复流程；启动时清理失败暂存和检查未完成导入。缩略图与原图分开，长列表不解码原始大图。

图片不以 Base64 塞入笔记正文，也不把绝对文件路径写进可迁移文档。回收站中仍有引用的附件不能被立即清理。

### 8.3 导出与备份

首版提供两种导出：

- 通用导出：Markdown + 附件，用于阅读和迁移；复杂格式允许降级，但说明可能的格式损失。
- 完整备份：版本化 JSON 文档、元数据、附件和 manifest，用于精确恢复标签、待办、稳定 ID 等关系。

对正在使用的数据库，不直接复制单独的 SQLite 主文件作为完整备份。WAL 模式下最新数据可能还在日志文件中；使用一致性快照或受控逻辑导出，附件也要与快照对应。SQLite 官方提供在线备份与快照方案，Android 端应按所选驱动的可用能力实现。[S11]

备份上传先写新版本，验证完整后再更新“最近成功备份”。失败不能覆盖唯一好备份。保留一组带时间戳的历史备份，允许用户配置保留规则。

首轮使用本地导出即可；继续 IdeaMemo 时，如果现有 WebDAV 备份可用，保留并验证。需要注意，WebDAV 上传数据库只能提供某种备份行为，不能自然获得多设备冲突处理能力。

### 8.4 恢复必须可预览、可回退

恢复流程：选文件 → 校验格式/大小/路径/附件 → 预览笔记与附件数量 → 先备份当前数据 → 在暂存空间试恢复 → 成功后事务切换。

防止 ZIP 路径穿越、异常膨胀压缩包、坏 JSON 和版本不兼容。恢复中的失败不能清空当前数据库。

“合并导入”与“整体恢复”是不同操作。遇到相同 UUID 且内容不同，创建冲突副本或让用户选择；不静默覆盖。

### 8.5 数据库升级

保留 schema 历史，写明确的 Room Migration，测试每个正式发布版本到新版本的可达路径。

正式应用不得用 fallbackToDestructiveMigration 解决迁移问题。Android 官方明确说明，缺少迁移路径时它会删除数据库中的数据。[S6]

如在已有 App 上二开，同时保留包名、签名与升级兼容性，避免做出“装上新 APK 就变成另一个没有旧数据的应用”。必要的身份变化要有迁移方案。

### 8.6 AI 衍生数据与删除

完整备份额外选择包含：对话、洞察、漫步历史、记忆与定时任务配置。服务密钥不明文混入普通导出；缓存向量可标记为重建项。

恢复定时任务时默认处于暂停状态，展示时区与下次运行再由用户启用，避免恢复备份触发一批旧任务。恢复笔记后重新计算索引与引用状态。

删除原文的规则需要逐层执行：活动查询立即排除；派生索引、记忆与缓存标记失效；已保存洞察和聊天中的引用显示来源删除。用户可选择连同衍生内容删除，系统明确保留期与删除进度。

需要保留完整历史证据的用户，可以选择保存来源快照；这个选择会延长相关文本保留时间，必须可见且可撤回。不能一边承诺彻底删除，一边在快照里隐蔽保留全文。

## 9. 中文搜索与提醒的真实难点

### 9.1 中文搜索

SQLite 内置 unicode61 tokenizer 将连续 token 字符看作一个词，不能直接当成成熟中文分词。trigram 按三个字符建索引，直接 MATCH 对短于三个字符的查询存在限制；“沟通”“作业”这种常见两字查询必须单独验证。[S7]

首期建议先实现正确的中文子串检索：在后台查询规范化 search_text，参数化 SQL、处理 LIKE 通配符转义，并在 1 万条数据集上测量。包含式 LIKE 往往需要扫描，达不到预算时再引入二元字符索引或合适的中文分词方案。

不要凭经验写死“Room 支持某版 FTS5”。实际可用能力取决于选用的 Room、SQLite 驱动、数据库构建与系统版本。是否使用自带 SQLite、FTS4/5 或自定义索引，应通过能力验证再定。

搜索规范化可包含大小写与全半角处理，但显示结果保留原文；简繁映射和拼音属于另外的检索策略，不静默修改用户笔记。

### 9.2 提醒

普通延后工作使用 WorkManager；用户指定“明天 8:00 提醒”需要 AlarmManager 等合适调度方式。WorkManager 的延迟和周期并不保证准确执行时刻。[S4]

Android 13 及以上新安装应用通常需要用户授予通知权限。申请应发生在第一次设置提醒时；拒绝后仍可保存待办，并显示“提醒未开启”。[S8]

精确闹钟权限与通知权限是两回事。按系统版本、用途和发布规则选择权限，检查 canScheduleExactAlarms，不假定精确闹钟权限已经授予。未获允许时明确呈现降级结果。[S5]

还要覆盖设备重启、时区变化、手动调时、权限被撤回、电池优化与强行停止后的状态。手机被关机或应用被系统强行停止等情况下，不能承诺通知照常到达。

时间模型区分一次性的绝对时刻与“当地每天 8 点”这类重复规则。本版包含单次提醒与基本重复规则；Agent 周期任务使用独立调度对象，必须测试时区、漏跑、重试和幂等。

### 9.3 语义检索的真实性

中文检索评估同时包含关键词完全不重合、否定表达、他人引用、时间已过期以及同主题相反立场。不能只用标题相同的样本证明检索有效。

语义相似度是检索信号，不向用户展示伪精确的“理解你 97%”。匹配理由来自可验证原文，必要时只说明“主题可能相关”。

## 10. 流畅度的验收方法

“感觉挺顺”只能作为体验反馈，交付还需要可重复的测试。

### 10.1 初始性能目标

以下目标先在选定参考设备上验证，再按真实结果调整。它们不代表已经达到，也不构成所有安卓手机的保证。

| 场景 | 初始目标 | 测量条件 |
| --- | --- | --- |
| 冷启动 | 可用首页 P95 ≤ 1.2 秒 | release 构建、固定设备、至少 10 次；同时记录系统启动指标与自定义可交互点 |
| 点击快速记录 | 面板可交互 P95 ≤ 150ms | 不包含第三方输入法冷启动；输入法完整出现另行记录 |
| 本地搜索 | 1 万条笔记查询本体 P95 ≤ 200ms | 不含输入防抖，固定数据集；无结果与高命中词都测 |
| 本地保存 | 短笔记事务 P95 ≤ 100ms | 不包含附件导入；UI 状态不阻塞 |
| 列表滚动 | 参考机关键场景卡顿帧占比争取低于 1% | 系统帧时限统计，连续滚动/快速 fling，各运行多轮 |
| 持续使用 | 切换、输入、滚动 10–15 分钟后没有持续增长的内存和明显劣化 | 冷机与温热状态分别比较 |

60Hz 每帧约 16.7ms，120Hz 每帧约 8.3ms。使用系统实际帧时限判断卡顿，不能将平均 FPS 当作唯一指标，也不能承诺应用一直强制维持 120Hz。

### 10.2 测试设备与数据

至少覆盖：你的日常 OPPO 安卓设备、一台 60Hz 中端机、一台 120Hz 设备；预算不足时优先日常真机和一台性能较弱设备。已有平板用于大屏与旋转测试。

用 0、100、1 万条笔记测试。1 万条样本包含约 1000 条带图片笔记、长短混合中文和中英混合内容；另准备 3 万字长文压力样本。大图只在需要时加载，不让测试变成全量解码竞赛。

标准测试场景：冷启动、快速新建、中文连续输入、列表滚动、开关键盘、图片详情、搜索、切换深浅色、切后台恢复、数据库升级、备份恢复。

### 10.3 优化顺序

先观察 trace，定位是主线程、布局、图片解码、数据库还是 GPU 特效开销。修复阻塞与无谓重组后，再调模糊区域、采样率和特效质量。

生成覆盖启动、记录、搜索和列表的 Baseline Profiles。验证 release 与 R8 配置；不凭模拟器或 debug APK 判断最终性能。[S2]

### 10.4 新功能的独立性能预算

本地卡片与缓存结果应即时响应。Agent 的“收到请求”反馈目标为 150ms 量级；首段有效回复的延迟按网络、模型与检索分别测量，不承诺统一秒数。长任务展示真实阶段和覆盖进度。

地图视口交互以设备刷新率预算验收，布局计算不得在手指拖动时抢主线程。测试 1 千、1 万和更大规模索引时的内存、首开、搜索和后台耗电，以实测确定全量展示与聚合阈值。

并发测试必须包含：正在转写音频时写笔记、Agent 流式回复时打开来源、地图更新时滚动列表。单独跑每个页面都流畅，不代表组合使用流畅。

## 11. 失败状态与质量矩阵

| 情况 | 页面行为 | 数据行为 |
| --- | --- | --- |
| 无笔记 | 一句提示和“记下第一条”，不放复杂引导 | 不自动塞入大量示例笔记 |
| 保存失败/空间不足 | 显示可操作错误，保留编辑区，允许复制内容 | 不声称成功，不丢弃内存草稿 |
| 导入图片失败 | 显示失败占位，可重试或移除 | 正文继续可用，清理临时文件 |
| 搜索尚未准备好 | 显示索引状态或提供慢速查询回退 | 不伪造零结果 |
| 无网 | 正常读写，备份状态单独展示 | 稍后重试备份 |
| 提醒权限拒绝 | 待办照常保留，明确提醒未启用 | 不登记为已成功调度 |
| 进程被杀 | 重开恢复最近已落盘草稿和位置 | 丢失窗口要通过故障测试量化 |
| 备份损坏 | 显示原因，不进入替换步骤 | 当前库完整保留 |
| 数据迁移失败 | 保留原库，进入恢复/导出方案 | 不破坏性重建 |
| 多设备未来发生冲突 | 展示冲突副本或合并入口 | 不用最后写入覆盖全文 |

必须有的质量测试：

1. 保存与并发：快速修改、连续返回、重复点保存、旧写入晚到。
2. 恢复：杀进程、旋转、系统回收、重启后草稿恢复。
3. 输入：Gboard、搜狗或设备常用输入法；拼音候选期间切格式、撤销、粘贴大段文字。
4. 迁移：旧版本库升级后笔记、附件、标签数量与关键内容一致。
5. 备份：完整导出再导入，稳定 ID、标签关系、附件校验值一致；Markdown 另验证可读性。
6. 中文搜索：单字、两字、三字、标点、emoji、中英混合、无命中、高命中。
7. 提醒：授权/拒绝/撤回、重启、时区变化、修改时间、完成与删除任务后的取消。
8. 视觉：大字体、横屏、深色、低透明度、不同导航模式和键盘高度。

### 11.1 AI 与探索功能验收

| 能力 | 必须通过的用例 |
| --- | --- |
| 每日回顾 | 同日卡组稳定；排除标签立即生效；桌面与 App 内容一致 |
| 漫步 | 可返回和续走；不困在少量重复卡片；结束统计来自实际路径 |
| 相关/找一找 | 无相同关键词也能找到标注相关项；无依据时不编造记录 |
| 洞察 | 引用 ID/版本正确；材料少时能承认不足；可从结果继续追问 |
| Agent 写入 | 用户明确指令可执行；失败不假报成功；重试不重复写入 |
| 记忆 | 更正优先生效；过期目标不会当现在；删除后不继续召回 |
| 定时任务 | 暂停/撤销生效；跨时区正确；漏跑不会无限补发 |
| 地图 | 聚合与覆盖范围可见；筛选有一致语义；命中能打开真实笔记 |
| MCP | 限定范围内搜索；跨用户读取为零；撤销后新请求被拒绝 |
| 语音 | 录音草稿可恢复；转写失败不丢音频；整理版可回到原文 |

准备一组有人工相关性标注的中文检索问题、含矛盾/引文/过期事实的记忆样本和完整操作脚本。通过率阈值在建立基线后确定，不能让同一个模型自评高分就算完成。

## 12. 部署、隐私与费用的现实选择

### 12.1 两种运行模式

| 模式 | 数据与运行位置 | 能力边界 |
| --- | --- | --- |
| 本地优先个人模式 | 笔记在设备；用户选择模型服务并授权发送所需材料 | 可记录、检索、手动洞察与对话；离线仍可读写和回看已生成结果；后台任务受设备限制 |
| 完整持续服务模式 | 安卓客户端 + 有身份认证的同步/Agent/调度服务 + 模型服务 | 支持应用关闭后生成、定时简报、远程 MCP 与跨端一致性；需要服务器和可控持续成本 |

产品正式蓝图覆盖第二种模式，并保留第一种作为可用退路。两者复用业务模型，不能为了开发省事把所有笔记先无条件上传。

本地生成嵌入和本地小模型可以作为可选后端，但需验证中文质量、模型体积、耗电与设备能力；未验证前不承诺全功能端侧 AI。

### 12.2 权限与数据使用

核心记录不强制注册；启用同步、远程任务或 MCP 时再建立对应身份。上传范围可按笔记本、标签和来源限制，用户能看到已授权范围和已同步覆盖时间。

同一授权范围里，检索可以自动进行。对范围扩大、外部分享和批量改写采取明确、少打扰的授权规则。日志不保存完整笔记、访问令牌或模型密钥。

应用锁与加密分开说明。云端 AI 处理需要在某个受控环境中读取授权内容，不能同时宣传“服务器完全无法读明文”却在服务器执行所有分析；若要端到端加密，须重新设计客户端解密及模型调用边界。

用户上传的网页、附件与检索片段是资料，不具有工具执行权限。Agent 不因资料中的指令扩大检索范围、外发内容或修改系统规则。

### 12.3 费用控制

成本拆成嵌入、模型输入/输出、语音识别、外部搜索、同步存储和任务运行。模型价格待选型时核对，本文不给未经实测的固定月费。

低成本顺序：只为新增或变更内容更新嵌入；漫步与日常回顾优先使用索引和规则；相同范围与版本的洞察允许复用；昂贵深度分析由用户主动发起或明确设为周期任务。

提供月预算、单次任务上限、工具循环上限、网络搜索次数和语音额度。费用估算与供应商账单区分；达到限制后保留草稿与已生成部分，不出现无限自动重试。

### 12.4 外部服务断开时

笔记、已保存回顾卡组、历史漫步和已生成洞察仍能查看。关键词搜索继续工作；语义结果是否可用取决于本地索引与嵌入能力。新 AI 请求显示待连接，用户可选择排队或取消。

定时任务明确最后成功运行时间和欠缺的资料范围，不能把昨天的结果当作今天刚生成。模型或服务商更换要做回归评估，尤其检查引用、工具调用和中文语音能力。

## 13. 实施里程碑与完整版本范围

先锁定完整产品合同，再按依赖施工。工程样例、内部测试版与完整体验版分别命名，不能用最早的可运行骨架冒充完整交付。

| 里程碑 | 实现范围 | 退出条件 |
| --- | --- | --- |
| M0：研究与技术样例 | 需求对照、现有仓库审查、完整页面原型、玻璃/键盘/检索/流式对话样例 | 确定关键技术风险、复用范围与模型候选；给出后续工作量估算 |
| M1：记录与可靠数据 | 文字/语音/附件、长文与清单、多级标签、引用反链、搜索、历史、备份与迁移 | 本地闭环与数据恢复通过；旧库升级不丢内容 |
| M2：重新发现 | 每日回顾、相关笔记、找一找、随机漫步与路径、桌面回顾 | 新旧笔记可形成有意义探索；排除范围和离线行为正确 |
| M3：洞察与 Agent | 多视角洞察、引用追问、原生 Agent、写回、记忆中心、技能与定时任务 | 从原文到洞察到对话到新笔记完整可用；动作与记忆可纠正 |
| M4：知识全景与连接 | 认知地图、关系图、统计、增量同步、外部 MCP/API、导入与分享 | 地图可定位原文；同步冲突、授权撤回与远程任务通过 |
| M5：整体发布验收 | 真机性能、耗电、故障、权限、费用、无障碍和跨流程回归 | F01–F20 功能合同逐项达标，未完成项明确列出并由用户决定 |

完整体验版应包含 M1–M4 的核心流程。3D 地图、更多视觉主题和额外第三方连接器可以增强迭代；已经明确要求的 Agent、漫步和洞察不能在排期时自动划成“以后再说”。

如果继续 IdeaMemo，M0 先审查现有数据与架构，沿用可靠代码。新功能按边界接入，避免一边改编辑器，一边整体重写存储，最后无法定位回归。

本版撤销上一版 6–10 周的粗估。增加 AI 检索、记忆、调度与同步后，工作量要经过 M0 的原型和仓库审查再估。复杂度应体现在明确任务、预算和验收里，不能成为擅自删减产品目标的理由。

## 14. 新范围下必须避开的坑

| 风险 | 具体问题 | 设计与工程处理 |
| --- | --- | --- |
| 只给聊天框取名 Agent | 无法读笔记、没有工具、没有持久记忆 | 用真实检索、工具动作、引用与记忆用例验收 |
| 把“能访问全库”写成每轮“读过全部” | 实际只取几个片段却做全局判断 | 报告实际范围、读取数量与抽样；全局问题单独聚合 |
| 漫步只是重复随机抽卡 | 无连续感，主题无关或原地循环 | 关联候选、多样性、路径去重、返回与用户反馈 |
| 洞察只改写一遍原文 | 看似有文采，却没有增量价值 | 明确视角、证据和可追问问题；允许材料不足 |
| AI 反复分析自己的输出 | 生成内容自我引用，逐渐污染记忆 | 保留 provenance，用户原文与 AI 衍生内容分开 |
| 把摘录当成用户立场 | 误造偏好与人格标签 | 区分自述、引文、虚构与推测；记忆可核对 |
| 旧目标永久有效 | Agent 一直按过去信息给建议 | 时间有效性、冲突状态、用户更正优先 |
| 删除原文但向量仍在 | 已删内容继续被召回 | 全链路失效、权限复核与删除任务 |
| 所有关系画成一种线 | 语义相似被误读为因果或手动引用 | 相似关系、显式引用和主题归属分别表达 |
| 每次地图刷新重新洗牌 | 无法形成空间记忆 | 稳定布局、版本记录、时间高亮优先 |
| 地图抽样不告知 | 用户以为画面代表全部记录 | 显示覆盖量、抽样方式和更新时间 |
| 服务器没数据却准点做周报 | 把旧索引误作实时完整资料 | 显示同步水位与覆盖时间，明确资料缺失 |
| 模型重试造成重复写入 | 同一笔记或定时任务出现多份 | action_id、幂等键、版本检查和可撤销记录 |
| 检索被私密范围过滤绕过 | 另一路召回泄露被排除资料 | 每个检索/取全文阶段都校验身份与范围 |
| 模型或网页偷偷触发操作 | 资料中的指令扩大权限 | 工具层授权与输入来源隔离 |
| 无限循环调用模型与搜索 | 用量和耗时失控 | 步数、token、搜索、费用与时间上限 |
| 每条笔记保存后强推 AI | 记录压力变大 | 保存后只给轻入口；主动回顾可设置时段 |
| 转写整理改变原意 | 人名、时间被润色成错误事实 | 保留音频和原文，可对照、重试和纠正 |
| 动效与 AI 同时抢资源 | 输入、列表和聊天一起卡顿 | 后台任务优先级、流式批量刷新、性能组合测试 |
| 微信/MCP 依赖未确认 | 整个产品卡在外部接入 | 原生核心可用，连接器单独核实与授权 |
| 全面实时玻璃 | GPU 成本高，文字受干扰 | 材质分级、有限采样区域、低效果档 |
| 保存/迁移不可靠 | 漂亮功能之下丢笔记 | 事务、草稿、历史、迁移和完整恢复测试 |
| 把备份当同步 | 多设备互相覆盖 | 增量变更、冲突副本、删除标记与独立备份 |
