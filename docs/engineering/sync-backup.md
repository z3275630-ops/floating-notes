# 保存、同步、导入与可恢复性

## 8. 保存、备份和迁移：发布前就要可靠

### 8.1 自动保存协议

快速输入保存为草稿，点击保存后正式提交；编辑已有笔记自动更新本地版本。

- 输入先进入内存编辑状态，短暂停顿约 300ms 后落盘。
- 持续输入也设置约 1 秒的最大合并窗口，避免仅 debounce 导致一直不写盘。
- 写入按笔记串行化或做 revision 校验，旧异步任务不能覆盖新输入。
- 每次保存提交文档及相关索引，附件使用可恢复的导入状态。
- 状态必须区分“正在保存”“已保存到此设备”“保存失败”。
- 用户明确退出编辑时尽量完成最新提交；正常生命周期回调也补做保存，但不能只依靠退出回调。
- 突然断电或进程被强杀时，尚未落盘的极短输入窗口仍可能丢失；开发时通过草稿恢复和故障测试尽量缩小，不能写“永不丢失”。
- 不把“已在本地保存”写成“已备份”，网络备份有独立状态。

### 8.2 附件

通过系统文件或图片选择器导入，及时复制到应用管理目录或正确保留持久授权。仅保存临时 content URI，过一段时间可能打不开。

采用临时文件 → 完整写入 → 校验 → 原子改名 → 数据库登记的可恢复流程；启动时清理失败暂存和检查未完成导入。缩略图与原图分开，长列表不解码原始大图。

图片不以 Base64 塞入笔记正文，也不把绝对文件路径写进可迁移文档。回收站中仍有引用的附件不能被立即清理。

### 8.3 导出与备份

首版提供两种导出：

- 通用导出：Markdown + 附件，用于阅读和迁移；复杂格式允许降级，但说明可能的格式损失。
- 完整备份：版本化 JSON 文档、元数据、附件和 manifest，用于精确恢复标签、待办、稳定 ID 等关系。

对正在使用的数据库，不直接复制单独的 SQLite 主文件作为完整备份。WAL 模式下最新数据可能还在日志文件中；使用一致性快照或受控逻辑导出，附件也要与快照对应。SQLite 官方提供在线备份与快照方案，Android 端应按所选驱动的可用能力实现。[S11](../research/sources.md)

备份上传先写新版本，验证完整后再更新“最近成功备份”。失败不能覆盖唯一好备份。保留一组带时间戳的历史备份，允许用户配置保留规则。

首轮使用本地导出即可；继续 IdeaMemo 时，如果现有 WebDAV 备份可用，保留并验证。需要注意，WebDAV 上传数据库只能提供某种备份行为，不能自然获得多设备冲突处理能力。

### 8.4 恢复必须可预览、可回退

恢复流程：选文件 → 校验格式/大小/路径/附件 → 预览笔记与附件数量 → 先备份当前数据 → 在暂存空间试恢复 → 成功后事务切换。

防止 ZIP 路径穿越、异常膨胀压缩包、坏 JSON 和版本不兼容。恢复中的失败不能清空当前数据库。

“合并导入”与“整体恢复”是不同操作。遇到相同 UUID 且内容不同，创建冲突副本或让用户选择；不静默覆盖。

### 8.5 数据库升级

保留 schema 历史，写明确的 Room Migration，测试每个正式发布版本到新版本的可达路径。

正式应用不得用 fallbackToDestructiveMigration 解决迁移问题。Android 官方明确说明，缺少迁移路径时它会删除数据库中的数据。[S6](../research/sources.md)

如在已有 App 上二开，同时保留包名、签名与升级兼容性，避免做出“装上新 APK 就变成另一个没有旧数据的应用”。必要的身份变化要有迁移方案。

### 8.6 AI 衍生数据与删除

完整备份额外选择包含：对话、洞察、漫步历史、记忆与定时任务配置。服务密钥不明文混入普通导出；缓存向量可标记为重建项。

恢复定时任务时默认处于暂停状态，展示时区与下次运行再由用户启用，避免恢复备份触发一批旧任务。恢复笔记后重新计算索引与引用状态。

删除原文的规则需要逐层执行：活动查询立即排除；派生索引、记忆与缓存标记失效；已保存洞察和聊天中的引用显示来源删除。用户可选择连同衍生内容删除，系统明确保留期与删除进度。

需要保留完整历史证据的用户，可以选择保存来源快照；这个选择会延长相关文本保留时间，必须可见且可撤回。不能一边承诺彻底删除，一边在快照里隐蔽保留全文。

## SY01：增量同步协议

本地 Note 是离线编辑权威，服务端是跨设备顺序与冲突协调权威。每次本地事务写 Outbox op_id、entity_id、base_server_revision、payload_hash、payload。客户端 push 后记录服务端 accepted_revision/冲突结果；服务端以 owner+op_id 去重，同 key 不同 payload 拒绝。

pull 使用服务端 opaque cursor，按固定批次读取变更与 tombstone。客户端在同一事务应用整页与新 cursor；中断重放不会漏页。按 server sequence 排序，不依赖客户端时间。初始建议页大小 200/单页上限 2MB，实际大小由服务端裁剪并明确 has_more。

服务端每个 entity 写入使用 expected revision。若等于当前 revision，提交下一版本；若当前内容 hash 与请求相同，返回幂等成功；其他情况返回 CONFLICT 和两个版本引用，不静默 last-write-wins 正文。

## SY02：冲突矩阵

| 本地/远端 | 决策 |
| --- | --- |
| 同一笔记不同正文 | 保存 conflict branch 两份；用户可保留双方或手工合并 |
| 标签不同字段独立修改 | 只在可证明不冲突时字段级合并，父级移动需重新防循环 |
| 待办同 block 同时改状态 | 不按客户端时间猜结果；保存冲突与来源版本 |
| 删除 vs 未同步编辑 | 主实体遵守 tombstone；未同步编辑保留为冲突副本，不自动复活被删 ID |
| 编辑附件 vs 对方移除附件 | 旧附件保留到冲突解决及保留期结束 |
| 旧客户端未知 block | 只读保留；禁止保存导致丢字段 |
| 相同 op 重试 | 返回原结果和 revision，不产生新事件 |

冲突副本不自动触发提醒、定时任务或记忆学习，防止重复副作用。合并创建新 revision 并标记解决双方分支。

## SY03：游标过期与删除防复活

tombstone 默认至少保留 90 天，并受活跃设备 ACK 水位约束；90 天不是无条件清理开关。长期离线设备超过同步租约后必须重新全量建立基线，将本地未推送变更作为受检冲突导入。不能带着旧 cursor 继续覆盖服务端。

服务端压缩变更日志前建立一致 snapshot watermark；新客户端拉 snapshot 后继续该水位增量。快照读取与游标起点必须在同一一致性协议下，避免全量期间遗漏写入。

## SY04：附件上传

创建 UploadSession → 获取有限期单对象授权 → 分片/完整上传 → 校验 SHA-256 与大小 → finalize → 关联笔记。对象键由服务端生成，不能接受路径穿越。客户端只拿限定对象的签名地址，不拿存储桶管理密钥。未完成上传可续传/取消；孤立对象按生命周期清理。

远端附件下载后校验再安装为本地 ready；缩略图与原文件分别缓存。删除回收站实体时不立即清理仍被版本、其他笔记或进行中备份引用的附件。使用延迟 GC 与引用扫描，GC 失败不影响读取。

## BK01：备份包格式

ZIP 内含 manifest.json、notes/*.json、metadata/*.jsonl、attachments/<uuid>.<safe-ext>。使用 schema_version、app_version、created_at、entity counts、文件大小与 SHA-256 列表。所有路径为相对路径；拒绝绝对路径、`..`、符号链接和逃逸目标目录的解压路径。限制总解压大小、单文件大小和文件数量，预检可用磁盘空间。

默认完整备份包括笔记/标签/引用/任务/版本/附件；对话、洞察、路径和记忆为明确可选项；授权 token、API key、会话密钥永不包含。向量、缩略图和地图布局可重建，manifest 明确省略。任务配置恢复为 paused。

一致性逻辑导出在固定 revision 水位读取数据，并给附件建立备份租约。数据库记录与附件版本对不上时备份失败，不发布“成功”的半包。写临时文件、校验、原子安装后才更新最后成功备份指针。

## BK02：恢复事务

校验所有文件 → 在临时目录/新数据库完整恢复 → 检查关系、计数、hash → 为当前状态生成回滚包 → 切换数据库与附件根指针 → 重建索引 → 最终报告。崩溃恢复依据 journal 完成/回退最后一步；不能先删除旧库再尝试导入。

整体恢复与合并导入分别命名。整体恢复前显示将替换的笔记数量，合并导入对重复 UUID 保留双方。新备份版本过高时拒绝并保留原文件，不“尽力读取”后静默丢字段。

## DL01：删除与 AI 派生数据

回收站操作立即影响默认查询和新的 AI 检索。清理时建立 DeletionJob，收集本地/远端正文、附件引用、chunks、embeddings、memory sources、evidence snapshot、缓存、地图快照索引及备份策略。

当用户选择彻底删除及其派生内容，立即撤销读取，异步擦除活动存储，目标 24 小时内完成活动副本删除；离线设备在上线后接收 tombstone。旧备份按明确保留策略到期，最长保留窗口需在实际部署中设定并向用户展示，不能宣称瞬间从所有备份物理消失。已发送给模型供应商的数据按供应商实际政策处理。

已有报告可保留用户单独保存的结论，但引用标记来源删除；若报告包含被删原文引用或保存的证据快照，应按用户选择一并脱敏/删除。引用索引不等于内容擦除；验收需要查原文、向量、缓存与快照。

## OP01：故障演练

至少演练：保存事务前/后杀进程、附件改名前/后杀进程、导入 50% 时崩溃、恢复切换时掉电模拟、同步 ACK 丢失、pull 页重复、过期 cursor、两个设备同改、磁盘满、坏 manifest。每次演练记录前后实体与 hash 计数，禁止仅凭 UI 可打开判断恢复正确。
