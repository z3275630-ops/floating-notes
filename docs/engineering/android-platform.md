# Android 平台适配与开发约束

## 9. 中文搜索与提醒的真实难点

### 9.1 中文搜索

SQLite 内置 unicode61 tokenizer 将连续 token 字符看作一个词，不能直接当成成熟中文分词。trigram 按三个字符建索引，直接 MATCH 对短于三个字符的查询存在限制；“沟通”“作业”这种常见两字查询必须单独验证。[S7](../research/sources.md)

首期建议先实现正确的中文子串检索：在后台查询规范化 search_text，参数化 SQL、处理 LIKE 通配符转义，并在 1 万条数据集上测量。包含式 LIKE 往往需要扫描，达不到预算时再引入二元字符索引或合适的中文分词方案。

不要凭经验写死“Room 支持某版 FTS5”。实际可用能力取决于选用的 Room、SQLite 驱动、数据库构建与系统版本。是否使用自带 SQLite、FTS4/5 或自定义索引，应通过能力验证再定。

搜索规范化可包含大小写与全半角处理，但显示结果保留原文；简繁映射和拼音属于另外的检索策略，不静默修改用户笔记。

### 9.2 提醒

普通延后工作使用 WorkManager；用户指定“明天 8:00 提醒”需要 AlarmManager 等合适调度方式。WorkManager 的延迟和周期并不保证准确执行时刻。[S4](../research/sources.md)

Android 13 及以上新安装应用通常需要用户授予通知权限。申请应发生在第一次设置提醒时；拒绝后仍可保存待办，并显示“提醒未开启”。[S8](../research/sources.md)

精确闹钟权限与通知权限是两回事。按系统版本、用途和发布规则选择权限，检查 canScheduleExactAlarms，不假定精确闹钟权限已经授予。未获允许时明确呈现降级结果。[S5](../research/sources.md)

还要覆盖设备重启、时区变化、手动调时、权限被撤回、电池优化与强行停止后的状态。手机被关机或应用被系统强行停止等情况下，不能承诺通知照常到达。

时间模型区分一次性的绝对时刻与“当地每天 8 点”这类重复规则。本版包含单次提醒与基本重复规则；Agent 周期任务使用独立调度对象，必须测试时区、漏跑、重试和幂等。

### 9.3 语义检索的真实性

中文检索评估同时包含关键词完全不重合、否定表达、他人引用、时间已过期以及同主题相反立场。不能只用标题相同的样本证明检索有效。

语义相似度是检索信号，不向用户展示伪精确的“理解你 97%”。匹配理由来自可验证原文，必要时只说明“主题可能相关”。

## 权限按具体动作申请

录音只在用户按下录音时申请麦克风。通知在用户设置第一个提醒或启用任务通知时解释。文件导入优先系统 Photo Picker/SAF，不申请全盘访问。媒体权限按具体 Android 版本核实；不能抄商店页面的权限长清单。精确闹钟权限与通知权限是两件事；被拒绝时保留任务并显示提醒能力状态。

录音需要前台可见状态与适当服务类型，后台启动和 microphone 前台服务限制按目标 SDK 文档实现。停止录音必须关闭资源与通知；电话/音频焦点变化测试。用户强行停止应用后系统限制无法绕过，不设计常驻保活骗局。

## 原生输入与窗口

编辑器维持一个稳定编辑会话，保留 selection/composing/undo。从数据库回流的旧值不能重设 TextField。语音/导入插入作为单一编辑操作保留撤销。中文拼音候选未提交前不自动格式化成块；`#` 建议和 `@` 引用不能破坏 composing 区。

WindowInsets 统一处理状态栏、导航栏、IME；edge-to-edge 下检查浅/深色系统图标。预测性返回按系统回调驱动；未提交草稿的退出语义遵守保存协议。大字体重新排版，不能整体缩小页面来塞入。

## 日程与时区政策

日期型 due_date 不等于 UTC 午夜。时间提醒记录 IANA zone 与本地时间；用户选择随当地时间还是固定原时区。夏令时不存在时刻默认推进到该日第一个有效时刻；重复时刻只运行一次，取较早 offset，并在预览中显示最终时间。测试使用真实时区规则，禁止写死 offset。

重复任务完成当前 occurrence 后创建下个 occurrence；历史完成记录保留。逾期提醒默认只汇总一次，不补发每个错过的间隔。设备重启、应用升级、时区改变重新核对未来提醒。AlarmManager 只能保证系统允许范围内调度，不能许诺所有 OEM 都绝对准点。

## 桌面小组件

使用 Glance/RemoteViews 能力边界。实时背景折射不能直接照搬应用内 Compose。组件采用同一色板、圆角和静态材质，保持可读；只展示允许在桌面出现的内容。刷新遵循系统调度，用户打开应用后主动更新。点击回顾卡使用 session_id/note_id，不能重新随机抽一张。

## 工程启动与发布身份

M0 建立可运行 debug 和 release 性能构建，保留应用 ID、versionCode、签名和构建环境记录。debug applicationIdSuffix 为 `.debug`，避免覆盖正式数据。建立测试数据导入入口，仅 debug 可用；正式包不包含样例账号和后台调试端点。

国内分发、Google Play 或自行安装的渠道规则在实际分发前核查。当前文档不声称满足备案、审核或上架要求，也不默认需要立刻上架。产品所有者先体验内测 APK，公开发布另行安排。
